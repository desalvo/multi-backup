Cloud Drive · esplora e gestisci

I cloud remoti sono configurati esclusivamente sul server. Download e navigazione sono disponibili in sola lettura; upload e cancellazione richiedono attivazione amministrativa e autorizzazione offline. La lista dei backup cifrati non equivale ad accesso ai loro contenuti in chiaro.

L'upload aggiunge un identificatore casuale al nome, senza sostituire file preesistenti. Per la cancellazione di un singolo file occorre confermare il percorso esatto e il suo SHA-256; la cancellazione è disabilitata per default.

Backup cifrati · ZIP64 · ripristino selettivo

Indica una cartella cloud contenente bundle.index.age e part-NNNNNN.zip. La verifica scarica e autentica tutti i volumi prima di visualizzare il contenuto. Questa funzione è Preview e disabilitata per default; richiede amministratore, HTTPS, CSRF e autorizzazione offline.

Recupero cloud disabilitato finché non viene abilitato dall'amministratore.

Il ripristino scrive esclusivamente su una nuova directory privata del server. Il ripristino direttamente verso un altro cloud remoto non è ancora disponibile.

Monitoraggio e API di stato

Prometheus 9502 e REST HTTPS 8443 sono abilitabili separatamente nella configurazione del server; SNMP usa Net-SNMP con accesso read-only. La REST accetta solo token scope monitor.read generati dall'applicazione, revocabili e salvati nel database soltanto come hash SHA-256.

La creazione/revoca richiede il codice offline di approvazione. Un nuovo token compare una sola volta: copiarlo in un secret manager.

Database interno · PostgreSQL HA e disaster recovery

La primaria PostgreSQL e le repliche Patroni sono comuni a tutti i server fisici e Kubernetes. I dump schedulati vengono cifrati prima della scrittura su disco e conservati nel vault S3 con Object Lock COMPLIANCE. La ricostruzione del database avviene soltanto in manutenzione offline, non da una pagina web.

Le operazioni richiedono amministratore, token CSRF e autorizzazione offline già inserita nell'area esportazione. Una replica che perde il lease viene posta in riconciliazione: non viene eseguito automaticamente un secondo writer.

Vault backup anti-ransomware

Lato server: copia cifrata verificabile dello store Multi Backup in uno storage separato. Ogni versione è nuova; nessuna API di delete o overwrite. Protezione ransomware effettiva solo con WORM/append-only applicato fuori dal processo.

Il restore richiede l’autorizzazione offline già presente nella sezione esportazione. Non scrive mai sullo store originale.

Notifiche SMTP(S)

Il server può inviare un messaggio di prova al destinatario configurato. La password viene letta da un Secret separato; TLS e certificato server sono obbligatori.

Esportazione selettiva

In modalità protetta, il ripristino richiede l'accesso amministrativo e un codice di approvazione indipendente, che non viene salvato dal browser.

Non condividere il codice di recupero con gli altri utenti. Il server non espone mai il vault.

Seleziona un singolo file o una cartella. Il restore viene verificato e scritto in una nuova directory sul server, senza sovrascrivere l'origine.

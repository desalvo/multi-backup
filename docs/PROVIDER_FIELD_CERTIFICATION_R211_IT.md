## Contratto
**Collaudato (funzione)** = test realmente eseguito sul provider/lab corrispondente, archiviazione cifrata, controllo indipendente di integrità e ripristino in nuova destinazione con prove negative. NON significa "Ready universale" di un plugin. **READY plugin** richiede tutte le B-In/B-Out e reverse directions promesse, credenziali least-privilege effettive, metadati/ACL applicabili, percorso crash/fault su failure domain indipendenti e prova provider reale sull'esatta build. Un runner hosted su un solo host, un unittest, un mock o il solo fail-closed non soddisfano il gate hardware/provider. Nessuna percentuale sintetica inventata.

## Prerequisiti operatori esterni obbligatori
1. Vault: 3 host con root e rete realmente indipendenti, utenti IAM non-amministrativi reali per provider impiegato, policy deny verificate server-side, retention COMPLIANCE, escrow receipt e private age key offline.
2. oVirt: oVirt Engine autorizzato con VM **usa-e-getta**, disk transfer e backup reali, OVF completo, tutti i dischi, guest boot e hash del dato interno alla VM; no accesso alla produzione.
3. PVE/PBS: self-hosted runner e environment protetto `multi-backup-pve-pbs-disruptive-lab`, un VM e CT già predisposti, ID destinazione nuovi, datastore destinazione isolato, autorizzazione esplicita. Per il boot finale limitare le VM a rete isolata.
4. VMware: vCenter/ESXi con licenza/API VADP supportata e una VM test isolata, nuova destinazione, CBT verificato, VM metadata/disks/guest data; non si può sostituire con stub HTTP.
5. Cluster database/FS: 3 host fisici quando si vuole certificare HA/fencing; lab su un'unica VM non basta. Compatibilità di prodotti/versions e failover vanno riportati per edizione realmente provata.
